# Bot 游玩、模型部署与多人房间

更新日期：2026-11-04。当前多人入口为 `python -m multiplayer.web`；独立试玩入口 `python -m multiplayer.bot_play --port 8772` 使用同一策略目录和默认部署模型，创建房间时仍自动安排三位 Bot。

## 策略与名称

目前共 21 项，分为七类。**精确 CFR 已从游玩入口移除，原抽象 CFR 统一称为 CFR**；底层使用 `AbstractCfrBot`，公开配置名为 `cfr-fast` 等，不再展示 `acfr-*` 或两套 CFR 菜单。历史研究源码不参与该菜单加载。

| 类别 | 配置 | 数量 | 数据依赖 |
| --- | --- | ---: | --- |
| 基础 | 摸切、随机、先胡随机 | 3 | 无 |
| 数学 | `math` | 1 | 无 |
| 搜索 | `search` | 1 | 无 |
| 启发式风格 | 速胡、做大、稳守、牵制 | 4 | 无 |
| NN | `nn-fast` 等 | 4 | `nn-policy.npz` |
| RL | `rl-fast` 等 | 4 | `rl-ppo-0068.npz` |
| CFR | `cfr-fast` 等 | 4 | `cfr-policy.json.gz` |

NN 与 RL 使用不同权重；CFR 使用抽象平均策略。NN/RL 的模型推理、CFR 的策略表命中和规则保底分别记录，不把未命中或预算不足的回退当作模型命中。血战暂未专门训练，仍显示兼容性提示，不据此宣称模型在血战中的强度。

## 部署模型

三份已经完成的游玩导出位于 `multiplayer/models/`，合计约 1 MB，必须随本私有仓库上传并打入 Docker 镜像。`manifest.toml` 记录来源和 SHA-256：

| 部署文件 | 来源 |
| --- | --- |
| `nn-policy.npz` | `.data/models/p4-v1/policy.npz` |
| `rl-ppo-0068.npz` | `.data/models/rl-3h/snapshots/ppo-0068.npz` |
| `cfr-policy.json.gz` | `.data/models/cfr-abstract-newrules-1h/policy.json.gz` |

RL 使用此前验证选中的第 68 轮，不把第 71 轮当作选中模型。CFR 使用新版规则的抽象策略，未复制精确 CFR 文件。原 `.data/`、训练检查点、日志和测试继续忽略；仅为部署 CFR 的确定路径添加 Git 忽略例外。

服务启动时先验证文件大小与摘要，再在 CPU 子进程中实际加载和预热。只有合同与摘要均通过才标记可用。缺失、损坏、依赖缺少或合同不兼容时，房主设置列出原因，对应策略禁用；无需模型的策略继续可用。不能在没有数据时把 NN/RL/CFR 静默换成同名启发式策略。

部署依赖包括 NumPy，用于 NN/RL 的 CPU 推理；不导入 Torch，不使用 GPU。模型整次运行固定，不读取训练中的 `latest`、`resume` 或临时文件，不热更新、不运行训练。未来更新需要替换已完成的游玩导出、同步清单摘要并重新部署。

独立试玩默认也使用这三份部署模型。`--model`、`--nn-model`、`--cfr-model` 可显式覆盖对应完成导出；`--no-models` 用于只开放九项无需模型的策略。旧 `--acfr-model` 参数仅保留为 `--cfr-model` 的兼容别名，不再指向另一类策略。

## 多人、人数与配置

每房最多 **十位真人和三位 Bot**。Bot 不占真人名额；成员面板显示真人人数，并另列 Bot 数量。Bot 可以候场，也可以与朋友混合安排四个牌局席位。Bot 没有浏览器身份或连接，不参与真人断线归因，同名登录不能接管 Bot。

房主可在首次开局前和安排下一局时添加、移除 Bot 或选择策略；开局后锁定。一个服务可同时运行多桌，所有 Bot 串行共享一个低优先级 CPU 子进程，按房间轮流调度。每次默认预算 500 ms，且不超过游戏窗口剩余时间；任务绑定房间、局、席位、控制权和行动窗口，迟到及失效结果不能落地。

计算超时或进程故障时，本局使用合法保底并在设置中说明。下一局由房主确认时可重新准备进程。Bot 只读取本人观察、公开历史和合法候选，不读取对手暗牌或未来牌山。

## 观战与整理

观众可以选择公共或上帝模式，并把任一座位放在主视角下方。上帝模式显示四家手牌；公共模式保持暗牌隐藏。视角切换不赋予该席位操作权、不改变牌局计时，也不暴露未裁决响应。

未胡真人可在 t1～t4 整理自己的手牌，包括自己的吃牌选择阶段。手动吃牌绑定原实体 ID，拖动不切换选择；加杠进入 t4 时绑定的实体牌不因整理而替换。暂停、托管和结算时禁用整理。t1 开启时固定等满；关闭后全员提交即可裁决；t4 保留全员决定后提前结束的规则。

## 玩家身份与重连

浏览器标签页使用随机凭证，已入房身份同时保存在同源浏览器的本地存储。普通重新打开页面会尝试原身份；顶栏“新玩家窗口”明确创建独立玩家。“我的身份”可切换此浏览器保存的身份。

断线或换设备后，直接输入原房间名、用户名和房间密码加入。服务先验证密码，再在同一房间锁内判断同名玩家的连接：仍有在线连接则提示用户名重复；已经离线则将新连接交给原成员，保留座位、手牌、分数及剩余宽限，废弃旧凭证。两个人同时重新登录时只允许一人成功接回；真人满十人时原成员重连也不增加人数。恢复码及单独的找回入口已移除。

默认断线交接容错 10 秒，非房主参赛者每席每局累计宽限 300 秒；超过宽限仍可接回原身份，但本局继续托管，下一局恢复真人。房主个人断线超过容错关闭房间；疑似全员断链先保护暂停，全员离线超过保留时间后回收。服务重启、关房或身份回收后，不能恢复已删除的内存状态。在线依据服务器确认的 WebSocket 连接，实际断网需等待连接检测完成。

## 验证与边界

本地回归覆盖：离线同名加入保留原成员与原手牌、在线重名和错误密码拒绝、多人竞争接回、原凭证失效、全员断线后的登录、公共/上帝四席观察、观众不能出牌、十真人加三 Bot 的容量，以及三份真实模型的预热和十二种学习策略返回合法动作。前端回归覆盖浏览器身份保存、新玩家隔离、登录前旧轮询作废、缺模型提示和观察座位选择。

测试、截图和开发依赖继续留在本地忽略目录。真实浏览器显示和云端异地复验需要部署后执行；自动化回归不代表策略强度评测或所有网络状况均已验收。
