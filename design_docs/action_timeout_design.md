# Action 与 Timeout

状态：开局理牌、四种行动计时、前端实体提交和统一权威最右默认出牌已实现。

## 动作与窗口

正式动作包括 `DISCARD / CHI / PENG / MING_GANG / AN_GANG / JIA_GANG / HU / PASS`。摸牌由后端流程推进。

| 阶段 | 可执行动作 | 计时 |
| --- | --- | --- |
| `HAND_PREPARATION` | 所有参赛者本地拖牌排序 | 独立理牌倒计时 |
| `WAITING_DRAW` | 后端摸牌 | 无 |
| `WAITING_TURN_ACTION` | 当前玩家出牌、自摸、暗杠、加杠或跳过提示 | t3 |
| `WAITING_RESPONSE` | 有资格者吃、碰、明杠、胡或过 | t1 |
| `WAITING_ACTION_DETAIL` | 吃牌者选择具体吃法或实体 | t2 |
| `WAITING_ROB_KONG` | 有资格者抢杠胡或过 | t4 |
| `SETTLING / ROUND_ENDED` | 结算及只读查看 | 无 |

动作校验所属实例、身份、局、控制权及对应窗口；涉及手牌时校验本人权威手牌版本。重复命令按 `command_id` 去重。版本和同步合同见 [联机设计](multiplayer_design.md)。

## 计时配置

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `discard_response_seconds` | 5 秒 | t1 |
| `action_detail_seconds` | 5 秒 | t2 |
| `turn_action_seconds` | 30 秒 | t3 |
| `rob_kong_seconds` | 5 秒 | t4 |

房间默认值由 `multiplayer/settings.py` 提供；底层 `TimeoutConfig` 可为无计时。开局前可设 1～600 秒或以 `None` 关闭。`GameConfig.fast_mode` 是独立开关，默认关闭，不依赖计时开关。本局配置锁定，安排下一局时可改。

## 开局理牌

网页每局发完四家各 13 张起手牌后，进入 `HAND_PREPARATION`。房主设置的 `hand_preparation_seconds` 默认 30 秒，允许 0～600 秒，0 直接跳过。该配置独立于 t1～t4 开关和快速模式，开局后锁定。

理牌期间可以本地拖牌，不能摸牌、出牌或吃碰杠胡，Bot 不提交策略动作。所有玩家及观众可见统一的 `HAND_PREPARATION` 倒计时；后端到期推进，庄家再摸第 14 张牌并开始完整 t3。暂停冻结剩余理牌时间，恢复后继续，不重发牌或重领 30 秒。

底层引擎默认理牌时间为 0，离线模拟和训练可直接开始；网页入口使用 30 秒默认值。

后端用单调时钟维护期限，独立推进 `expire_timers(now)`。客户端只显示倒计时；没有客户端轮询、超时消息或排序上传时，后端也能完成默认处理。无计时时等待需要决策的真人明确行动；断线托管见 [运行与断线](hosting_design.md)。

## t1：弃牌响应

| 模式 | t1 有计时 | t1 无计时 |
| --- | --- | --- |
| 普通 | 固定等满 t1，即使全部提前决定；只有过的玩家静默过，其他玩家到期未提交默认过 | 所有其他有效席位明确响应，包括只有过的玩家，全部提交后裁决 |
| 快速 | 只有过的玩家自动过；无人能要牌时立即跳过 t1，否则等相关玩家全部决定或到期后裁决 | 只有过的玩家自动过；无人能要牌时立即跳过 t1，否则等相关玩家全部决定后裁决 |

“能要牌”包含吃、碰、明杠和胡，资格由后端合法选项判断。快速模式不增加客户端自动过或跳时请求，不改变 t2、t3、t4。

普通计时模式固定等待，用于隐藏响应资格；快速模式允许提前轮转。两种模式都不向其他玩家公开待裁决意向。

```text
HU > MING_GANG > PENG > CHI
```

- 一炮多响开启时全部合法胡牌声明生效；关闭时保留沿出牌者下家方向最近的赢家。
- 同级碰杠按座位距离决定，与点击先后无关。
- 吃只允许下家；血战使用下一有效席位。
- 全部过或到期后无人认领则下一有效席摸牌；碰后直接进入 t3，明杠先补摸，吃进入 t2。快速模式也必须收齐所有有资格者的最终决定，不能因第一人点击而提前忽略其他响应。

碰、明杠的实体由前端在提交响应时选定，后端私下绑定，胜出时重新验证并按 ID 执行。之后继续整理不替换实体，策略见 [手牌整理](hand_order_design.md)。

## t2：吃牌细节

吃法按牌值方案去重，同值实体的不同 ID 不算不同吃法：

- 不超过 5 种时列出方案；点击后前端按当前手牌顺序从左到右选实体。
- 超过 5 种时进入手动模式，玩家选择恰好三张实体牌。

两种模式确认时均提交具体 `selected_tile_ids`。后端检查归属、无重复、数量、方案和合法算式。

无效选择、未选择、主动放弃或超时均结束本次吃牌并按 `PASS` 处理，不重新裁决低优先级响应；之后由原弃牌者的下一有效席摸牌。

胡、碰、杠均不进入 t2。胡法由后端规则计算器选择最高番结果，客户端不手选胡法。

## t3：当前玩家行动

摸牌后进入 t3，生成自摸、暗杠、加杠和出牌选项。本次摸牌由稳定 `drawn_tile_id` 标识，自摸上下文不受本地拖动影响。

有杠提示时先选择杠或 `PASS`；`PASS` 只跳过本次胡/杠提示，不结束回合、不刷新计时。后续新的 t3 重新判断机会。

出牌将有变化的完整 `hand_order` 与实体合并为一个请求。后端先检查期限、窗口和合法性，再原子更新顺序并执行；失败不留下部分排序。具体协议见 [手牌整理](hand_order_design.md)。

### 超时出牌

所有 t3 超时统一先放弃未处理的胡/杠提示，再打出后端最近权威快照顺序最右实体。前端未提交的排列和高亮不参与选择。

| t3 来源 | 超时前的权威顺序 |
| --- | --- |
| 普通摸牌 | 原顺序右侧追加新摸实体 |
| 吃、碰完成 | 移除实际消耗实体，其余顺序保留 |
| 各类杠成功补摸 | 移除杠牌消耗实体，右侧追加补摸实体 |

快照是后端最新实际手牌，不依赖浏览器是否收到回包。摸牌或补摸后的最右牌通常就是新增牌，但默认选择始终依据权威顺序，`drawn_tile_id` 不增加特殊优先级。

若出牌请求处理时已到期，后端先处理唯一一次超时，拒绝旧动作且不应用其排列。前端从当前本地布局按 ID 删除真正离手的牌，其他顺序不变，也不补发排列。

```text
后端快照：A B C D E
前端排列：E C A D B
超时出 E：前端变为 C A D B
```

### 杠与补摸

前端随暗杠、加杠动作提交具体实体，后端验证后执行。暗杠、明杠及无需抢杠窗口的加杠完成后补摸，开启新的完整 t3。

牌山为空时禁止杠，包括刚摸走最后一张牌的情况。牌张数量由合法动作方案决定，不套用传统麻将张数。

加杠有抢杠资格者时进入 t4，没有资格者则直接完成。补摸更新 `drawn_tile_id`，吃碰后无摸牌的 t3 清空旧绑定。

## t4：抢杠响应

只有加杠可被抢，明杠和暗杠不触发 t4。

- 进入窗口时保存加杠方案和绑定实体，暂不移牌、不升级碰组、不补摸，暂停原 t3。
- 有资格者只能提交一次最终 `HU / PASS`；到期未提交默认过，无计时则等明确响应。
- 全部合格玩家决定后可立即裁决；已有胡牌声明不会因其他人超时而丢失。
- 一炮多响和最近赢家规则与 t1 一致。

全过后才完成加杠并补摸，恢复原 t3 剩余时间，不赠送完整时长。例如原剩 18 秒，t4 结束补摸后仍剩 18 秒。

有人抢杠胡时，只移除绑定的加杠实体，保留碰组，不补摸；普通模式结束，血战按后续规则继续，不进入此次加杠成功后的 t3。

t4 禁止常规出牌和再次杠牌，但未胡玩家仍可合法本地整理；拖动不替换待加杠实体。

## 展示与权限

- 普通参赛者仅收到本人有权查看的倒计时；t2 属于吃牌者，t3 属于当前玩家，t1/t4 按响应资格过滤。
- 加杠者在 t4 只看到本人暂停的 t3 剩余量。
- 公共观众不看暗牌和私人倒计时，上帝观众按权限只读查看，不获得行动权限。
- 服务器过滤未公开响应、实体选择和未来牌山，不能只靠 CSS 隐藏。
- 副露按后端 `display_tiles` 的顺序和朝向显示；吃横放被吃牌，碰和明杠横放来源牌，暗杠两端背面，加杠在原碰组右侧加正立牌。

## 验收重点

覆盖普通固定 t1、无计时人工确认、快速模式跳过空响应和提前裁决、t2 无效选择、多人胡牌、各类杠及抢杠、各来源 t3 超时、迟到请求和计时竞争。布局与实体验收见 [手牌整理](hand_order_design.md)，血战继续流程见 [血战设计](blood_battle_design.md)。
