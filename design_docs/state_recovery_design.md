# 状态快照与牌山记录

在线服务使用内存状态，重启清空，不加载 SQLite 检查点。引擎保留独立快照能力；正常结算后的牌山记录保存在当前开服内存中。

## 引擎检查点

`simulator/state_snapshot.py` 提供：

```python
capture_game_state(game, now=...)
restore_game_state(snapshot, now=..., rule_adapter=None, scoring_adapter=None)
```

捕获与恢复不自动发牌、摸牌、裁决、计时到期或结算。完整检查点属于服务器私有数据，不通过客户端状态、观战、静态目录或下载接口公开。

当前格式 v5 保存快速模式、理牌时长及进行中的理牌倒计时，支持普通和血战状态，兼容恢复 v1～v4；旧版缺失的新选项默认关闭，不给已有牌局补加理牌阶段。旧手牌整理元数据丢弃，仅保留实体顺序。检查格式、枚举、牌值、实体 ID、席位、窗口、结算和适配器合同；未知版本或损坏数据拒绝恢复，不重发牌补救。

| 分类 | 保留内容 |
| --- | --- |
| 牌局 | 游戏/局 ID、阶段、庄家、当前席、模式和计时配置 |
| 牌张 | 完整剩余牌山顺序、各席手牌及稳定 ID、后端顺序、副露朝向和弃牌 |
| 窗口 | t1/t2/t3/t4 身份、资格、选项、已提交响应、实体绑定和剩余时间 |
| 结算 | 已完成事件、结算 ID、分数变化和最终结果 |
| 计时 | 相对时间及暂停状态，包含 t4 内部暂停的 t3 |

适配器按认可类型和规则版本恢复，或显式注入匹配对象；不从快照动态导入类，不序列化锁、线程、数据库连接或 Socket。恢复不重算已有结算。

## 时钟与存储

保存相对剩余时间，恢复时用新单调时钟重建期限。无计时仍为无计时，已提交响应保留，不能赠送完整操作时间。嵌套暂停分别恢复；t4 全过只补摸一次并恢复原 t3 剩余量。

`simulator/state_store.py` 提供 SQLite 原子记录、版本和摘要校验。记录放在非静态数据目录，旧写不能覆盖新版本。当前房间服务未接入该存储。

## 前端布局

高亮和未提交排列只在浏览器存在，不属于服务器检查点。刷新时，有效本地布局按实例、身份、局和权威实体集合合并；没有有效本地布局时按服务器顺序初始化。

权威更新只删除离手 ID、追加真实新增 ID，保留其他本地顺序。换身份或换局不能复用旧布局，详见 [手牌整理](hand_order_design.md)。

## 结算后的牌山查询

`multiplayer/round_review.py` 在洗牌完成、发牌之前记录完整抽取顺序，再标注起手发牌、普通摸牌、各类杠后补摸和剩余牌。

- 记录绑定局 ID、规则版本、轮次和当局名字/座位，按实际抽取顺序显示。
- 仅已有正常 `RoundResult` 且房间处于 `REVIEWING` 或 `ARRANGING` 时开放。
- 所有当前房间成员可查，房主和上帝观众不能提前看牌山。
- 确认新开局后停止旧局查询，不泄露新局牌序；关服清空记录。
- 没有记录完整初始牌序的局显示不可用，不能由剩余牌山编造历史。

接口为 `GET /api/local/wall-record?room_id=...&round_id=...`，校验身份、当前房间、当前结算局和阶段。日常状态只带可用性标记，点击后才读取；前端切换对象或新开局时丢弃迟到响应。

完整逐步回放、历史下载和在线服务持久化不属于当前能力。
