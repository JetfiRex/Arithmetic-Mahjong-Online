# 房间聊天

右下角提供可收起的聊天浮层，默认收起并显示未读数。桌面不改变牌桌布局，手机使用浮层。昵称、时间与内容均按纯文本显示。

## 使用

- 同房真人玩家和观众共用频道，理牌、对局、暂停、结算及局间都可聊天。
- Enter 发送，Shift+Enter 换行；中文输入法选字不触发发送。
- 每条最多 300 字，服务端按成员限速，每秒恢复一条、短时允许三条。
- 发送独立于游戏 `busy`；失败保留输入，可用原消息编号重试，收到确认后再清理对应输入。

## 同步

复用 `/api/local/presence` 的已认证 WebSocket，不新增轮询或额外连接，不把聊天放进牌局快照或事件日志。接收聊天只更新聊天 DOM，不重绘牌桌。

| 类型 | 内容 |
| --- | --- |
| `chat_sync` | 房间 ID 与最后收到的 `after_id` |
| `chat_history` | 缺失的保留记录、最新 ID 与历史截断标记 |
| `chat_send` | 房间 ID、客户端消息编号与文字 |
| `chat_message` | 服务端顺序 ID、作者身份/昵称、时间和文字 |
| `chat_error / chat_resync` | 聊天错误、可选重试等待时间或重新补取通知 |

进入房间及重连时补取缺失消息，历史与实时推送按顺序 ID 合并去重。补取位置只推进到连续收到的位置或已确认的历史快照，避免并发推送乱序时跳过缺失消息。更换身份、房间或服务实例时清理旧缓存；下一局保留聊天。

每个房间保留最近 100 条消息，另保留有限的重试编号。全部仅存内存，关房或服务器重启后清空。

## 运行边界

昵称和成员身份从服务器取值，不接受自报作者；每次读写及推送发送前校验当前房间成员和有效连接。离房、被移出或凭证失效后不能继续收发旧房间消息。

聊天不校验行动窗口、手牌版本或托管控制权，也不修改牌局、房间配置版本和倒计时。错误只返回聊天提示；不占住房间锁等待网络，文字校验在锁外完成。

## 开销与维护

广播只遍历当前房间的订阅连接，一条消息只编码一次。每条连接有独立写任务，慢连接不会拖住其他接收者。

| 项目 | 上限与处理 |
| --- | --- |
| 待发队列 | 每连接最多 32 项；待发及发送中的数据预算为每连接 256 KiB、全服合计 8 MiB |
| 积压 | 清理该连接的待发内容，发补取提示；小型恢复通知允许超出数据预算 |
| 历史补取 | 每连接、每房间最多每 5 秒一次；限速后前端延后自动重试 |
| 聊天请求 | 每连接每秒恢复 5 次、短时允许 10 次，非法 JSON 同样计入；超限后暂停读取 0.2 秒形成背压 |
| 清理 | 断开时移除订阅、取消发送任务并释放缓冲；关房清理历史 |

不增加聊天轮询、数据库写入或逐条消息日志。日常查看平台 CPU、内存和现有 `/healthz` 健康检查；若玩家反馈卡顿，先对照聊天活跃时段与牌局操作延迟。健康检查能发现 tick 停滞，不能代替实际延迟观测；当前未增加单独的聊天监控服务。
