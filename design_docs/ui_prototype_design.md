# 共享浏览器牌桌

多人房间与人机试玩共用 `UI/static/` 牌桌和样式，通过 `multiplayer/static/client.js` 接入服务。手牌整理在前端本地完成。

## 页面区域

- 主牌桌：来牌或摸牌、牌山张数、阶段、四家弃牌和对手状态。
- 手牌带：公开副露与一条本地手牌顺序。
- 操作带：当前可执行动作，吃法仅在 t2 展示。
- 成员面板：座位、房主、在线状态、观战和 Bot 设置。
- 房间聊天：右下角可收起浮层，未读数、消息记录和独立输入区；不改变手牌区域布局。
- 房主设置：独立的快速模式开关，计时关闭时仍可使用，开局后锁定；顶栏显示当前快速模式。
- 开局理牌：默认 30 秒，可设 0～600 秒，0 跳过；主牌桌显示统一倒计时，期间只可排序，结束后庄家开始回合。
- 结算与牌山弹窗：胡法、番种、分数和本局完整牌序。

房间页面不提供修改手牌或牌山的开发者入口。

## 选牌与显示

普通出牌左键单选，确认出牌才提交实体 ID；手动吃牌选择三张实体。自动选牌按当前本地顺序从左到右匹配。

选择绑定 `tile_id`，同值牌不能替换。出牌和吃牌高亮跟随各自窗口。

数字模式让数值和运算符居中，外观切换不改变牌尺寸。副露按后端 `display_tiles` 的顺序、横放和牌背标记显示，不重新猜测来源牌。

## 牌面素材

24 种牌面预先打包为一张 6×4 图集，每格 210×300，覆盖当前手牌在高 DPI 屏幕的显示尺寸。页面头部预加载，手牌、弃牌、副露、观战和弹窗共用 CSS 图集，不再逐张请求原图；图集失败时仍有数值和运算符标签。

图集文件名带内容摘要，允许浏览器缓存一年；素材变化后引用新地址。页面、脚本、样式、身份和牌局数据继续使用 `no-store`。图片在开发时生成，服务端运行时只发送静态文件。

修改 `pictures/` 的牌面后，在仓库根目录执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File UI/build_tile_atlas.ps1`，生成新图集并同步 HTML、CSS 和服务端白名单。检查新增图集与引用一起提交；此参数仅作用于该次构建进程。

## 拖牌与状态更新

拖动、落点、排序和高亮即时在前端完成，零整理请求，不进入全局 `busy`。正式动作等待期间，状态接收和合法的本地整理继续。

手牌节点按 ID 复用，插入线复用，落点不变时不改 DOM。命中和排序规则见 [手牌整理](hand_order_design.md)。

权威状态只增删真实牌张，不恢复旧排列。超时删除后端选定的实体，其余本地顺序保留；新摸牌追加到手牌右侧。旧回包不能覆盖后续整理。

正式出牌才附带有变化的顺序。有暗牌权限的观众看到成功提交后的排列，不看到拖动、高亮和待裁决选牌。

## 权限与适配

未胡参赛者在开局理牌及 t1～t4 可整理；暂停、托管、已胡及结算时禁用。观众可选公共/上帝模式和观察座位，但不能替该席操作。

窄屏允许手牌横向滚动，成员侧栏改为抽屉。鼠标、触屏和键盘需分别验收，不以桌面拖动通过代替触屏通过。

## 验收重点

- 拖牌、选牌和吃牌高亮稳定，同值实体不混淆。
- 拖牌不回弹等待服务器，连续整理不阻塞，更新不重建正在拖的有效实体。
- 桌面、窄屏和高 DPI 下无溢出，牌面与数字模式尺寸一致。
- 观战旋转、暂停、托管、结算和下一局符合权限及阶段。
- 整理请求为零，正式出牌仅一次提交，超时不依赖客户端消息。
