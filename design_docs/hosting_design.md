# 联机运行与断线处理

当前服务使用内存房间，重启清空。部署参数见 [README](../README.md) 和 [云端部署](cloud_deployment.md)。

## 运行

- `python -m multiplayer.web`：多人房间；`python -m multiplayer.bot_play`：独立人机试玩。
- 单实例、单 Uvicorn worker，后台 tick 约每 0.1 秒推进计时和自动动作。
- tick 异常后停止推进，异常或长时间停滞时 `/healthz` 返回 503。
- 不加载 SQLite 存档；关闭浏览器不停止进程，部署或进程重启清空本次开服。
- Bot 在有预算的 CPU 子进程计算，模型在开局前准备，不占住房间锁等待加载。

## 连接与刷新

在线依据服务器确认的 WebSocket。连接先校验精确 Host/Origin，再在五秒内校验首帧凭证和实例 ID；凭证不放 URL。

同一身份最多八条连接，最后一条消失才记失联。刷新允许新旧连接交接；HTTP 动作必须绑定有效 `connection_id` 和 `control_epoch`。

房间聊天复用此连接，按当前成员权限推送。独立有界发送队列避免慢连接阻塞牌局；聊天记录只保留在当前房间内存中，见 [房间聊天](chat_design.md)。

Uvicorn 传输心跳当前 ping 间隔 5 秒、pong 超时 10 秒。确认失去连接后另有默认 10 秒交接容错，实际断网检测还取决于传输层。

## 断线影响

| 失联者 | 处理 |
| --- | --- |
| 未胡的非房主参赛者 | 容错后全桌暂停，等待重连 |
| 房主，包括观战房主 | 个人失联超过容错后关房 |
| 普通观众 | 不暂停牌局，到期回收身份 |
| 血战已胡的非房主玩家 | 不再阻塞牌局 |
| 疑似全服同时断链 | 保护暂停，等必要成员恢复 |

非房主参赛者默认每席每局累计 300 秒宽限。暂停冻结游戏计时，包括开局理牌倒计时，保留已提交响应和 t4 内部暂停的 t3；多人分别消耗宽限，重连不重领。

宽限内回来后恢复剩余时间；耗尽转本局默认托管，回来仍只能查看，下一局可重新安排为真人。原身份仍有在线连接时不能被同名登录接管。

## 默认托管

- t1、t4 只过，t2 放弃吃牌；普通计时 t1 仍等满，快速模式沿用全部相关决策完成即裁决；全员决定的 t4 可提前结束。
- t3 跳过胡/杠提示，再取后端最新权威顺序最右实体；关闭 t3 也自动推进。
- 不等待前端未上传排列，不替真人运行策略 Bot。
- 真人、托管和计时进入同一串行通道，旧控制权或迟到结果不能再行动。

出牌规则见 [计时设计](action_timeout_design.md)。

## 全员断链与回收

所有相关真人连接消失，且至少两名成员包含房主在短时间内同时失联时，运行层保护暂停，冻结游戏计时及已开始的个人宽限；原房主和仍需真人控制的席位恢复后继续，普通观众不阻塞。

这一信号用于保守处理，不保证准确区分网络故障与同时主动关页。全员离线超过 `SESSION_TTL_SECONDS` 后回收房间，默认 3600 秒。对局中的离线席位保留凭证至本局结束，其他离线身份按保留期回收。

房主关房或个人失联关闭的未完成局直接作废，不生成假结算或改分，其他房间不受影响。

## 入口边界

精确校验来源、身份、消息大小、速率和连接数；不信任转发身份头，不开放仓库或开发者编辑接口。日志不记录邀请码、Bearer 凭证、房间密码和暗牌。

真实异地及物理断网验收见 [云端部署](cloud_deployment.md#真实异地验收)。
