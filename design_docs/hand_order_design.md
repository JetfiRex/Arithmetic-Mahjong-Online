# 手牌排序与实体选牌

手牌只有一条本地顺序，副露单独显示。拖牌、落点判断和高亮在前端完成，不发送整理请求，也不进入全局 `busy`。正式动作等待期间仍可合法排序并接收状态。

## 本地排序

- 使用稳定 `tile_id` 标识实体，同值牌也不能混用。
- 开局理牌及 t1～t4 期间，所有未胡玩家可拖牌；暂停、托管、已胡及结算时禁用。
- 手牌提供首位、牌间及末位插入槽；副露不是有效落点。
- 移动前验证身份、局、牌张集合、本地版本和索引，非法移动保持原顺序。
- 手牌节点与插入线复用，落点不变时不改 DOM；滚动、缩放或落牌时更新几何信息。
- 普通出牌左键单选；手动吃牌选择三张实体，拖动不改变已选实体。
- 出牌及吃牌高亮随各自行动窗口清理，新摸牌追加到手牌右侧。

开局理牌默认 30 秒，由房主调整。结束后庄家摸牌追加到右侧，前端保留已经整理的顺序；理牌期间不额外上传排序。流程见 [Action 与 Timeout](action_timeout_design.md)。

## 正式出牌

一次出牌命令携带 `command_id`、实例、房间、局、控制权、手牌版本、行动窗口和要打出的 `tile_id`。顺序变化时附带完整的出牌前 `hand_order: list[tile_id]`，未变时省略。

牌值、坐标、图片和高亮不上传。后端检查身份、去重、期限、行动合法性和排列完整性，再原子执行；非法、过期或重复命令不能部分改顺序或多出牌。

有暗牌查看权限的观众在成功出牌后看到提交顺序；真实摸牌、消耗和副露正常同步，未提交排列及高亮不广播。

## 吃碰杠选牌

前端按合法方案所需牌值，从当前本地手牌左到右取匹配实体，同值需求按数量计数。手动吃牌直接使用玩家明确选择的三张实体。碰、明杠、暗杠和加杠使用相同的顺序规则。

| 动作 | 提交实体的时点 |
| --- | --- |
| 碰、明杠 | 点击 t1 响应时 |
| 吃 | t2 确认列表吃法或手动选牌时；t1 只声明吃 |
| 暗杠、加杠 | 提交对应 t3 动作时 |

后端验证窗口、时间、归属、重复 ID、数量、牌值和方案，绑定提交实体，执行时重新核对。继续拖牌不替换已提交选择。无效吃牌按本次 t2 的 `PASS` 处理。

加杠进入 t4 前绑定实体；被抢杠只移除该牌并保留碰组，全过后完成加杠、补摸并恢复原 t3 剩余时间。

## 超时与状态合并

所有 t3 超时及断线默认出牌取后端最新权威顺序最右实体，不等待客户端消息。权威顺序计入成功提交的排序、吃碰杠消耗、摸牌和补摸；不取决于浏览器是否收到快照。

前端按权威牌张集合合并当前本地顺序：删除实际离手的 ID、清理失效选择、追加新牌，其余相对顺序保留。旧回包不能覆盖后来整理的顺序，合并结果不再上传。

```text
后端顺序：A B C D E
本地排列：E C A D B
超时出 E：本地保留 C A D B
```

权威手牌版本与本地排序版本分开。实例、身份或局变化时隔离旧排序；没有有效本地排序时才按服务器顺序初始化。计时细节见 [Action 与 Timeout](action_timeout_design.md)。

## 验收

- 连续拖牌与高亮产生零整理请求，正式出牌只提交一个请求。
- 正式动作等待、快照乱序和超时不冲掉后来整理的顺序。
- 同值实体、吃碰后及杠后超时都删除正确实体。
- 观众只看到有权查看的已提交状态，不能看到私有排序或待裁决选牌。
